# The Ox Tracker: build tools only. Exact pins with hashes.
#
# These go into a SEPARATE build venv, by default
# %USERPROFILE%\.venvs\the-ox-build, never into the runtime venv.
# packaging\build.ps1 creates that venv and installs, in this order:
#
#   python -m pip install -r requirements-build.txt --require-hashes
#   python -m pip install -r requirements.txt       --require-hashes
#
# The second line is there because PyInstaller can only freeze what is
# installed next to it, so the build venv needs the app's own dependencies
# as well. Both files are installed with --require-hashes: a package whose
# SHA-256 does not match is refused rather than frozen into the app.
#
# PyInstaller and everything it depends on, verified against PyPI on
# 2026-09-22. This is the ONLY file that pins them: requirements.txt holds
# the app's runtime packages and nothing else, and no package appears in
# both files, so the build venv can never be asked for two different
# versions of the same thing. tests/test_guards.py checks that.
#
# No UPX. PyInstaller only uses UPX if it finds it, and the build script
# passes --noupx regardless: compressed executables are a common reason for
# antivirus false positives, and they save little for a one-folder app.
